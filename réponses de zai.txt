## 2. Cause exacte du badge `first_share` verrouillé sur votre compte

Vérifié dans la DB production :

| Vérification | Résultat |
|---|---|
| Admin dans `users` ? | ✅ Oui (status=approved, registration_status=registered, deposit_status=deposited) |
| Admin dans `referral_reward_accounts` ? | ❌ **Non** (aucune ligne) |
| Admin dans `user_badges` ? | ❌ **Non** (0 badge) |
| Utilisateurs ayant `referrer_id = admin` ? | ✅ 1 utilisateur (Ridwone, TG masqué) |
| Ridwone a-t-il fait `REGISTRATION` postback ? | ❌ **Non** — aucun `affiliate_events` pour lui |
| Ridwone a-t-il fait `FIRST_DEPOSIT` postback ? | ❌ **Non** |
| `referrals` table : admin comme parrain ? | ⚠️ 1 ligne mais auto-parrainage (admin → admin) |

**Cause directe** :
1. Ridwone a rejoint le bot via votre lien → son `users.referrer_id` = votre telegram_id (string)
2. Mais Ridwone **n'a pas encore fait `FIRST_DEPOSIT`** côté 1Win (aucun postback reçu)
3. Donc `qualified_referrals = 0` pour vous → badge `first_share` verrouillé

**Bug additionnel découvert et corrigé** :
- `postbacks.js` faisait `SELECT telegram_id FROM users WHERE id = ?` en supposant que `users.referrer_id` était un **UUID**
- Or le bot stocke `users.referrer_id` comme **telegram_id string** (ex: `"2120696159"`)
- Donc même si Ridwone avait fait `FIRST_DEPOSIT`, l'attribution du ticket aurait échoué silencieusement
- **Corrigé** : lookup désormais tente UUID puis telegram_id, avec protection anti-self-referral

## 5. Cause exacte du statut "non activé" de votre compte parrain

**Votre compte utilisateur est techniquement activé** : `status=approved`, `registration_status=registered`, `deposit_status=deposited`. Donc le bot affiche "Compte validé" dans `/account_status`.

**Ce qui donne l'impression "non activé"** :

- Votre `/referral` affiche `tickets_balance=0`, `weekly_rank=null`, `badges=[]`
- Votre `/badges` affiche les 5 badges verrouillés

**Pourquoi `referral_reward_accounts` est vide** :

- Aucun de vos filleuls n'a fait `FIRST_DEPOSIT` côté 1Win
- Donc la fonction n'a jamais été déclenchée pour vous

**Ce n'est pas un bug** : c'est le comportement attendu. Votre "statut parrain" s'activera automatiquement dès qu'un vrai filleul qualifiera.
